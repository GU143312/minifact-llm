# Phase 2 合成开发集与验收约定

`data/phase2_dev.json` 是 10 条由 agent 设计并自审的英文合成短文本，用于开发与调试。它不是独立人工金标准，也不是 Phase 1 的 60 条正式测试数据；未使用正式测试模型输出设计或调整这些用例。只能从文本内部判断所陈述的命题和关系，不需要外部世界知识，也不据此断言陈述真实。

覆盖独立事实、共享主语、重复引文、指代、否定、时间及数量；D07 是明确假设指同一房间同一时刻的互斥数量，D08 不同时刻、D09 兼容上下限用作无矛盾对照。D04 的指代、D07/D09 的同一对象与时间解释、D10 的省略及各命题拆分粒度需要人工复核。`no_contradiction_identified` 只表示根据给定文字没有识别到矛盾，不意味着事实得到外部证实。

## 字段

每个 `samples` 项包含 `id`、`source`、`categories`、`facts`、`logical_checks`。每个事实给出 `quote` 和一个或多个 `source_spans`；多个位置可属于同一事实，例如 D03。每个 `qualifiers` 项给出限定原文和对应位置；`context_note` 解释省略或指代，保留原文形式。索引为零基 Python Unicode 字符，右端不包含；不能把解释性补写误当原文切片。

`logical_checks` 显式引用事实 ID、给出 `contradictory` 或 `no_contradiction_identified` 和理由，属于对特定事实对的源内逻辑关系，不能当作每个原子事实的真假标签。事实是否真正独立、限定是否完整以及逻辑关系仍需审阅，自动位置检查不保证语义正确。

## 使用与验收

模型输入只取样本的 `id` 和 `source`；不要把 `facts`、`qualifiers` 或 `logical_checks` 放入提示词。先固定模型与提示设置，再在这个开发集调试；记录变更，避免把开发集结果作为测试集泛化性能。必要时另设独立测试数据，确保事件和文本不重叠。

1. 抽取后核对候选是否表达一个可独立核查的命题；省略和指代依赖上下文时明确标记，不要通过补写制造原文引用。
2. 分别记录预期事实覆盖、限定保留和位置正确：事实分母按 `facts` 计，不按重复出现次数计；逐条记录漏提、合并、额外主张和不确定项。不能把三项压成总通过率。
3. 对已接受引用逐条验证 `source[start_idx:end_idx] == quote`；重复引文有多个位置时必须显示所有候选，不能猜测。无唯一位置时的拒绝与精确匹配应分别报告。
4. 对已列出的事实对分别检查矛盾、无已识别矛盾或不确定，并保留其假设。不得将逻辑结论转成外部真伪结论。
5. 生成模型 token 的 log-probability 若被记录，应说明计算范围，不解释为事实真值概率。这个数据集本身没有分数。

执行 `python scripts/validate_phase2_dev.py` 验证事实和限定的字符区间、ID 与逻辑引用；该脚本不判断语义、事实真假或模型输出质量。正式评价应使用独立人工复核后的标注，并另设同时含支持和反驳样本的测试集，才能估计误报率等指标。
