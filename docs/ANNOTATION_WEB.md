# 本地标注网页

2026-11-23。为 `next_eval_v2` 的 60 条独立初审提供 A/B 两个单文件网页。标注者使用表单、原文选择和按钮操作，不需要编辑 JSON。两人各自独立完成同一批样本，再共同仲裁。

## 使用

1. 将 B 分享包直接转发给同学，自己使用 A 页面。先解压，再双击对应 HTML，以 Edge 或 Chrome 打开。
2. 填固定化名；选中原文后点“用选中文字新增主张”，填写完整主张，必要时选取上下文依据、添加限定条件。
3. 逐字位置自动计算，重复引用会列出全部位置。事实是否独立、是否提全及限定是否保留仍由人工判断。
4. 勾选复核并确认本条完成。任何事实编辑都会让本条回到待办。可搜索、筛选已完成或待办、前后切换样本。
5. 页面尝试在当前浏览器本地保存；每次结束前下载草稿并确认下载成功。换电脑、浏览器或网页路径时，用“恢复进度”导入备份。
6. 全部完成后导出 `reviewer_a.json` / `reviewer_b.json` 回传。导出时需要确认独立人工标注，并记录实际时间。HTML 文件自身不会包含后来填写的进度，请回传导出的文件。

网页仅用于独立初审；仲裁和正式实验仍遵循 [原指南](NEXT_EVALUATION_ANNOTATION.md)。草稿为带角色与数据版本的可恢复文件；正式完成稿与现有 Python 校验器兼容。生成包总是从原文重建空白模板，绝不打包已填写的 reviewer 文件。

## 构建与测试

```powershell
python scripts/build_annotation_app.py --bundle data/next_eval_v2 --output outputs/annotation_web_v1
node --test tests/annotation_app.test.cjs
python -m unittest discover -s tests -p test_annotation_app.py -v
```

生成器拒绝覆盖已有目录。A/B 压缩包各自只含一个 HTML、`先读我.txt` 和来源许可 `NOTICE.md`。代码、样本均内嵌，无 CDN、服务器、模型或上传接口。大模型及环境不在包内，正式数据、标注模板和冻结的评估代码不受此工具修改。

本地保存可能被浏览器限制，因此提供手动草稿备份；多窗口同时修改同一角色时暂停冲突页面的自动保存。原文、填写内容和导入数据通过文本节点显示。引用索引按 Python Unicode 字符计算，覆盖重复出现和非 BMP 字符。

## 验证边界

7 项 Node 核心测试及 Python 包装/跨语言契约测试通过。使用独立合成 QA 页面实际验证了选择引用、新增两条事实、时间/数量限定、上下文、完成检查、刷新恢复、编辑后回到待办、草稿下载/导入和完成稿下载。下载所得两条合成事实通过原 `check_facts`；这些是界面测试数据，不是任何正式人工标注。真实 A/B 页面仍为 0/60，展示和导航已检查。

交互通过 localhost 预览验证。浏览器工具的 URL 策略禁止自动打开 `file://`，因此未自动验证双击打开行为；未绕过该限制。交付 HTML 完全内嵌且无联网依赖，供标注者自行双击使用。页面不能认证真实身份，也不能自动证明语义标注正确。
