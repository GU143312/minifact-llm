# Week 6：整条主张比较测试集

本版把**原有 60 条 Refuted 样本与 50 条新选 Supported 对照**合并为 110 条英文新闻相关短主张，用于比较直接判决与抽取—验证流程的整条样本级表现。原 60 条样本的 ID、原文、标签、QA、来源和其余字段完整保留；`data/phase1/` 文件没有改动。它们已经有此前实验输出，不能称为从未见过的测试集。

| 文件 | 用途 |
| --- | --- |
| `dataset.json` | 主数据：整条原文、上游整条标签、解释、证据 QA 和来源 |
| `inputs.json` | 运行记录接口，仅 `id` 和 `text`；实际模型提示词只接收 `text` |
| `curation.json` | 来源版本、原 60 条文件哈希、规则、逐条排除理由、最终对照行号、数据文件哈希 |
| `dataset.schema.json` | JSON Schema Draft 2020-12，固定 110 条及字段范围 |
| `NOTICE.md` | 数据署名、原论文、许可与改编说明 |

`MF-P1-*` 是原 60 条 ID，`MF-P3-C-*` 是新对照 ID。**ID 前缀能区分入选队列，不能进入模型提示词。**标签、QA、核查链接、上下文元数据及选择规则也不作为闭卷输入。输入顺序按独立 SHA256 排序确定，使两组交错，不能依据类别分别运行或挑选结果。

## 固定来源与选择

沿用作者仓库 [AVeriTeC](https://github.com/MichSchli/AVeriTeC) 的 `data/dev.json`，revision `7c62d1ec8df3fb560d6efe2b85fa191135636f81`，整文件 SHA256 `499793726b4a5406780928a3d9dedc48d6dd53de778f22437d129cacdb08e300`。上游共 500 条，其中 Supported 122 条。来源行号是这个固定数组的零基下标，不冒充作者提供的 ID。

1. 从 Supported 中使用与 Phase1 相同的结构规则：8–65 个空白分词；有解释及核查文章；至少一个有 HTTP(S) URL 的非 Unanswerable Web text/PDF 答案；排除明显依赖视觉的类型/原文、非文本证据以及开头指代不明等记录。94 条通过这一步。
2. Agent 查看主张与解释，定向检查可疑 QA，记录 25 个来源行号的排除理由。例：Forbes 排名只有循环引用 Facebook 主张；World Food Program 与 World Food Program USA 范围不同；精确数字与 QA 不符；时间混淆、缺少国家指代、定性预测或显露 `Fact Check` 编辑判决的标题。另排除来源行号 123，因为它与原样本行号 119 是同一 PHE 流感/Covid 报告故事，虽文章链接不同。
3. 对余下 69 条使用 `SHA256("minifact-phase3-controls-v1|42|来源行号|原文")` 排序。先把原 60 条的规范化文本及核查文章加入去重集合，再逐一加入对照；每个规范化文本及核查文章最多一条。规范化采用 Phase1 规则（忽略大小写及非词字符；文章解除 Wayback 外层、去片段及末尾斜杠）。同一篇文章中的不同主张也只保留一条。
4. 上限预设 60 条，最后只有 **50 条**通过去重，因此保留全部 50 条，不用含糊记录补足数量。具体重复行号及原因见 `dataset.selection_audit`。这项文章去重不保证不同文章从未报道同一故事；除记录的语义排除外，没有建立独立人工事件聚类。
5. 对照按来源行号分配 ID；合并后使用 `SHA256("minifact-phase3-input-order-v1|42|项目ID|原文")` 排列运行顺序。所有 JSON 用 UTF-8、LF 保存，哈希按实际字节计算。

这些对照**没有按类型、国家、来源域名或句长与错误样本统计匹配**。原 60 条有既有筛选和不同的历史排除过程；现在 50 条对照采用上述新增筛选。类间分布和质量筛选带来的偏差必须随比较结果报告，不能把测试集准确率外推为真实新闻总体准确率。筛选过程中没有调用本周实验模型，也没有按其输出删样或改标签。

## 数据概况和标签边界

| 项目 | Refuted | Supported |
| --- | ---: | ---: |
| 样本数 | 60 | 50 |
| 核查域名数 | 18 | 19 |
| 空白分词长度（平均） | 9–47（19.65） | 8–49（16.60） |
| 上游日期范围 | 2020-08-26–2020-10-29 | 2020-08-26–2020-10-26 |
| QA 问题 / 答案 | 142 / 151 | 123 / 134 |
| Event/Property / Numerical / Quote / Causal / Position | 29 / 8 / 13 / 8 / 2 | 26 / 15 / 3 / 4 / 2 |

`gold.verdict` 为 `REFUTED` 或 `SUPPORTED`，`gold.verdict_scope` 固定 `whole_sample`。标签和证据继承上游历史标注，没有独立人工重新裁决，也没有逐条在线复核；不能称为已经证实的当前真伪。原始拼写、上下文缺失、可能的上游标注问题以及 `required_reannotation` 标记均保留。公共 dev 数据也可能出现在模型预训练材料中。

一个整条 Refuted 标签不表示所有抽出的原子事实都错。`annotations` 中原子事实、限定条件与错误类型仍为 `null`。原 60 条的旧状态字符串 `pending_days_3_4` 为保持字段不变而保留；新对照记为 `not_annotated`。本集可以衡量**整条预测与上游标签的一致性**，不能直接给出原子事实提全率、限定保留率或原子判决准确率。文字位置继续由逐字切片单独检查。

评估必须明确错误为正类、整条预测规则和无有效输出/弃权的处理；分别列分母、混淆矩阵、准确率、漏报和弃权，不能把上述抽取维度合成一个通过率。Supported 对照只是增加正常类可观测性，没有解决闭卷知识、历史时间或独立证据不足的问题。

## 校验与重建

离线校验无需模型、GPU、原始下载或网络（依赖 `requirements-data.txt` 中的 jsonschema）：

```powershell
python scripts/build_phase3_testset.py --check
python -m unittest discover -s tests -p test_phase3_dataset.py -v
```

使用仓库外的固定版本源文件进行逐字节重建检查：

```powershell
python scripts/build_phase3_testset.py --source <缓存目录>/dev.json --check
# 去掉 --check 才会重建；冻结实验完成后不应覆盖这一版本。
```

无 `--source` 的检查验证 schema、原 60 条文件哈希和逐条完整保留、上游记录哈希、固定对照清单、日期、标签范围、唯一文本/文章、统计、输入字段隔离及冻结的数据字节哈希。有原始源文件时，还会验证整文件哈希、重新执行选择并核对输出字节。大文件与模型缓存留在仓库外的 E 盘。
